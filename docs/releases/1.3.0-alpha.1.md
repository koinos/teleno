# Teleno native 1.3.0-alpha.1

Release date: 2026-10-19. Channel: **experimental alpha**.

This prerelease publishes the accumulated Teleno development work on
`codex/lr2-memory-hardening`: startup diagnostics, lossless backup/restore and
storage improvements, memory ownership, networking, RPC, dependencies and the
mainnet producer repair. It is an independent native release. Koinos One's
packaged runtime and submodule pin remain separate.

The node preserves complete canonical history and existing block/receipt
records. This release does not introduce a light node or a pruning policy.
Issue 9 and full LR2 qualification remain open. Measurements below describe
their identified development binaries, inputs and durations; they do not turn
an alpha into a generally qualified low-resource profile.

## Startup and operator diagnostics

- Add local-only `--preflight` and `--preflight-json`: strict configuration
  validation, runtime/dependency/resource observations, filesystem checks,
  temporary TCP bind probes and producer-key metadata checks.
- Exit before creating a basedir, opening databases, restoring data or starting
  services. Reports retain explicit unverified synchronization, integrity,
  network and production requirements.
- Correct Linux RSS reporting to use resident pages rather than virtual size.
  Add database memory attribution and producer/mempool/VM activity metrics.
- Document native setup, configuration, public RPC/admin boundaries, observer
  recovery, troubleshooting, container operation and exact build identity.

## Backup, restore and storage

- Add explicit direct CLI restore planning, staging, resume and activation.
  Stream checked backup objects into one staged database without retaining a
  second object-cache copy. Verify metadata authentication, pinned source and
  chain identity, object sizes/hashes and cooperative cancellation.
- Retain a durable attempt journal and ownership locks through validation and
  activation. Use same-filesystem renames with interrupted-activation recovery;
  preserve observer-first startup and the producer recovery hold.
- Reuse a freshly verified activation scan within the same locked operation;
  standalone/interrupted operations validate afresh and final post-rename
  validation remains mandatory. Reserve bounded HTTPS read-buffer capacity to
  reduce small checked writes without relaxing transfer checks.
- Add `--backup-restore-reserve-profile experimental-8gib` for the measured
  profile, retaining the greater 20%-of-database reserve. The standard CLI
  default remains `max(10 GiB, database bytes / 5)`; the selected experimental
  profile uses `max(8 GiB, database bytes / 5)`.
- Add optional persistent block-table Zstd level/dictionary policy and explicit
  offline `--compact-db --compact-rewrite`. Existing tables remain readable;
  other column families and zero/default settings retain their behavior.
  Dictionary training and workspace are bounded. Existing tables are rewritten
  only by an explicit operator action.
- Add an optional soft total-WAL-size flush trigger and improve RocksDB
  accounting. A soft trigger is not a hard disk ceiling.
- Publish archived block records and highest topology in one atomic write
  batch; refuse inconsistent persisted topology. Tighten checkpoint/source
  identity, durable publication and transfer failure reporting.

Direct restore remains opt-in. Repository restore remains the default. These
changes do not expose a public administration API, upgrade a running backup
publisher or replace an operator's public backup automatically.

## Mempool, state and memory ownership

- Perform native mempool admission before accepted-transaction notifications;
  classify local capacity refusal separately from invalid transactions.
- Make scoped multi-fork admission and head expiry/removal failure-atomic;
  preserve nonce, RC, tombstone and root invariants across retries.
- Share immutable serialized pending records across forks. Add opt-in
  lifetime-owned record/capacity reservations and standalone transaction-work
  job/input-wire reservations, with counters for active, peak and refused work.
- Preserve partially decoded/copied Protobuf records through allocation
  failures and publish ownership only after successful preparation.
- Keep immutable owners attached to state reads/iterators and share immutable
  map-clone payloads. Correct cache accounting, hit allocation and eviction
  behavior; oversized retained values can bypass caching without changing
  execution.

These component policies do not bound every retained fork, index, caller,
encoding workspace or allocator contribution. They are not a whole-process
memory guarantee, and unlimited/default axes are not silently replaced by
machine-specific limits.

## Networking and RPC

- Own connected and retired sync-worker generations through draining and
  shutdown. Bound disposable accepted-ID retention without suppressing still
  pending work.
- Complete short Peer RPC writes before reporting success. Accumulate
  fragmented reads in an owned buffer and use constant-stack MessagePack
  skipping. Retain borrowed buffers through completion/cancellation.
- Apply one response deadline across open/write/read phases; distinguish
  cancellation/local overload from peer misconduct and narrow later block
  batches after local receive-capacity refusal.
- Correct peer-score grouping, decay and saturation; bound optional error,
  candidate, advice, explicit-dial and SDK-address bookkeeping with
  lifetime-owned reservations and failure-atomic publication. Protect
  configured roots and live connections from optional eviction.
- Replace unsafe external metadata reads with synchronized native views;
  collect disposable metadata with the owning runtime generation.
- Own HTTP sessions, request lifetimes and deadlines. Release completed request
  and response bodies while keeping in-flight buffers alive.
- Serialize and release JSON-RPC batch results individually into the complete
  response body, preserving response bytes/order, dispatch semantics and
  strict UTF-8 error behavior.

Protocol framing and public RPC behavior remain compatible. Aggregate SDK,
caller, decoded-response and output capacity/lifetime qualification remains open.

## VM and pinned native dependencies

- Protect parsed-module ownership through allocation failures and make cache
  publication optional/failure-atomic. Coalesce cold parsing while retaining
  fresh mutable execution instances and unchanged protocol metering.
- Add an optional attributed parsed-module byte budget and cache metrics.
  Default bytes remain unlimited with the existing 32-entry ceiling; oversized
  modules execute without retention. Smaller caches can increase parsing CPU
  and latency.
- Use one hash-pinned Fizzy build recipe with a narrow context-allocation fix:
  allocation failure stays a local failure instead of terminating in `noexcept`.
- Correct unaligned host result-count stores with byte copies at their original
  sites, preserving alias ordering and execution results.
- Rebuild the pinned Koinos Protobuf runtime with failure-safe unknown-field
  publication and arena-string construction. Preserve public headers, wire
  bytes and existing installed dependencies.

## Producer repair and compatibility

- Recover from the producer/head/mempool handoff that reports
  `cannot retrieve pending transactions from an unknown block`.
- Retry only the typed transient missing-parent condition or an observed head
  change, at 10 ms. Discard stale cached candidates. Expose the persistent
  condition after 100 consecutive deferrals and retain unrelated failures.
- Preserve pending transactions; no empty-mempool replacement or indefinite
  exception suppression is introduced. Add candidate, PoB evaluation, head and
  mempool retry, and error counters.
- Preserve native 1.2.1's 131,072-byte external system-call result capacity and
  exact missing archived receipt-root completion. Refuse conflicting records;
  do not invent missing receipts or repair historical omissions.
- Retain its isolated observer/large-bytecode/receipt/cold-restart regression,
  deterministic backup missing-object fixture, hash-pinned GMP mirror, bounded
  downloads and explicit CI test roots.

## Release artifacts and CI

- Retain the exact clean Linux binary, version/help output and full native JUnit
  report from the release workflow. Build metadata records the commit, compiler,
  binary hash, actual linked archives and every committed source-file hash.
- Use an absolute CTest report path so the retained qualification artifacts
  correspond to the completed test run.
- Prevent native prerelease container tags from replacing `latest`. The default
  `beta` channel follows `main`; the alpha uses explicit version and commit tags.
- Apply dependency patches within the verified extracted archive, independently
  of a surrounding or inherited Git worktree. Keep every original archive and
  patched-file hash check; nested-checkout and redirected-worktree regressions
  exercise the corrected bootstrap path.
- Discover exact Protobuf `3.17.3.0` in the Hunter directory scope. The package
  wrapper's function-local version variable previously caused fresh builds to
  fail before compiling the node. The dependency revision and public headers
  remain unchanged.
- Preserve reusable dependency build state after a failed CI bootstrap, and
  keep timestamp-only container metadata out of native compilation cache keys.

## Demonstrated development evidence

The operator-owned reference profile is Ubuntu/x86_64/ext4, two vCPUs,
approximately four decimal GB RAM, no swap, and a strict 40,000,000,000-byte
whole-server budget. OS, software, databases, WAL, logs, temporary workspace and
the held reserve count toward that budget.

- The selected-backup 8-GiB experiment restores, validates, activates and
  reopens the complete backup. Restore peaks at **37,915,475,968 bytes** including
  the reserve. Retained-reader compaction peaks at **39,352,967,168 bytes**;
  all **46,458,363** compared current/checkpoint/reopened records match.
- Its finite five-hour observation completes **18,007.577 seconds** and
  **9,360 steady reads without failure**, including clean and controlled
  interrupted recovery. Original archive records remain byte-identical.
- The repaired development candidate passes **63 distinct native checks** and
  a full **60-minute** mainnet producer observation. Peak native RSS is
  **223,084,544 bytes**; minimum host MemAvailable is **3,230,367,744 bytes**;
  whole-server accounting peaks at **38,186,901,504 bytes** including reserve.
  Mean CPU is **18.879% of one core**; successful local head-RPC p95 is
  **3.405 ms**. No OOM or swap occurs.
- Its separately authorized continued observation records own mainnet block
  **40,323,375** at **2026-10-18 21:35:48 UTC**, independently canonical and
  irreversible. It contains zero transactions. The same producer stays running
  without a restart; publication does not replace its executable.

These predecessor runtime identities and source relationships are retained in
the [producer report](../validation/native-producer-handoff.md),
[8-GiB report](../validation/vps-8gib-recovery-reserve.md) and
[completion matrix](../validation/low-resource-lr2-completion-matrix.md).
Release assets record the exact alpha commit, native binary/dependencies,
version/help checks and release-specific regression/container results. Earlier
measurements are not relabeled as measurements of a new release executable.

## Remaining qualification and operational boundaries

Issue 9 remains open for aggregate memory/workspace policies, integrated
sanitizer/lifecycle coverage, the full required historical differential range,
sustained mixed-load/recovery checks and final whole-node qualification. The
general 24-hour/seven-day gates are separate from the completed five-hour
compaction/reserve experiment and finite producer commissioning.

The alpha does not establish every optional legacy service, arbitrary future
backup size, unlimited chain growth, every compaction pattern or a loaded
mainnet producer. Component diagnostics and earlier binaries retain their own
limits. Review the exact source/input evidence before selecting runtime options.

Mainnet activation, financial transactions, backup-publisher administration and
running-node deployment retain their existing authorization and identity gates.
Keep owner custody material off the producer host and start restored nodes as
observers. No keys, wallets, operational databases or access material are release
assets. The alpha artifacts are unsigned; verify their SHA-256 checksums.
