# Teleno native 1.3.0

Teleno 1.3.0 combines the qualified M1 memory implementation with the Fogata
GossipSub/listener lifetime fixes and the changes previously published in
[alpha.1](1.3.0-alpha.1.md) and [alpha.2](1.3.0-alpha.2.md). It is an independent
native-node release; it does not upgrade a running node or a Koinos One package.

## Memory ownership and admission

The opt-in `mempool.aggregate-max-accounted-bytes` policy now follows retained
native allocations through their real lifetime. Coverage includes shared
pending records, retained forks, map/index/tombstone nodes, nonce/RC/count
metadata, transaction work, decoding/staging workspace and selected caller/RPC
outputs. Immutable aliases share credits; independent copies retain their own.
Admission reserves capacity before allocation/publication and releases credits
when the final owner releases the allocation.

Block/LIB changes, fork transitions and persistent index publication prepare
throwing work before mutation. Local admission refusal preserves accepted
transactions and supports a later retry. Canonical and recovery operations
remain attributed but quota-exempt, so local policy cannot prevent valid
canonical processing. JSON-RPC local overload, gRPC resource exhaustion and
P2P scoring remain distinct from transaction validity and consensus behavior.

The default aggregate limit remains **zero (unlimited)**. The measured R15
profile uses 768 MiB of ordinary admission, 64 MiB of HTTP refusal workspace
and 1 MiB of gRPC refusal controls. These are tested application policies,
not physical heap/RSS ceilings or a guarantee for every input. Preserve the
separate transaction-count/input-wire policies and their defaults. See
[configuration](../configuration.md) and the
[ownership inventory](../implementation/issue-9-m1-owned-memory-inventory.md).

## Fewer copies and reliable cleanup

- Move decoded transaction values instead of copying them into query results.
- Avoid temporary nonce-key and synchronous JSON parameter/string copies.
- Release redundant encoded input before native transaction execution.
- Dispatch already-built in-process block events directly while preserving
  serialized fallback behavior for other RPC client implementations.
- Clean owned JSON trees without new helper allocations. Apply a pinned
  dependency backport for partial JSON copies that outer guards cannot own.
- Preserve Protobuf unknown fields, repeated values and generated oneof
  ownership through allocation failure. Fix shorter-predecessor read bounds.
- Preserve resource failures during base58 normalization instead of retrying
  another encoding with changed native input/classification.

Neutral and worse physical-memory results are retained alongside successful
measurements. Removing allocations does not by itself prove lower process RSS.
The R15 controlled HTTP workload shows a 7,917,568-byte reduction in the
peak-RSS difference of medians across five pairs; other component allocation
reductions do not establish attributable RSS savings. These predecessor
measurements do not claim an equivalent saving for this release binary.

## HTTP and gRPC output lifetime

Selected HTTP/gRPC response allocations retain credits until the actual final
buffer, status, registry and callback owners finish. HTTP capacity replies
stream borrowed request IDs and use a separate bounded refusal workspace.
When that workspace cannot be admitted, the connection closes without
executing refused work.

gRPC refusal controls have a separate aggregate allowance. Detailed status may
fall back to a code-only overload response. If even control setup cannot be
admitted, a build-owned gRPC call-binding correction makes early cancellation
safe before native transaction work. Persistent or unrelated failures remain
visible; a local limit is not silently converted into success.

## Fogata P2P lifetime corrections

External GossipSub publication previously entered mutable cache state outside
the SDK runner. Publication now queues owned work on that runner with finite
pending-message/byte limits and retires work with its transport generation.
The pinned SDK listener callback acquires a weak owner before dispatch, avoiding
use of a destroyed listener manager across stop/restart. Three native
regressions cover publication/heartbeat, loopback ingress and concurrent stop.

Both defects were reproduced separately. The exact instruction responsible
for the original 2026-10-21 producer heap-corruption abort is still unknown
because no readable core was retained. See the
[validation summary](../validation/fogata-gossip-publication.md). This release
must not be described as proof of an unlimited mainnet producer lifetime.

## Other changes since stable 1.2.1

The alpha.1 history documents the complete earlier change set, including:

- Full-history single-copy backup staging, validation, activation/recovery
  markers and explicit disk-reserve policy; no history or receipts are pruned.
- Lossless archive/storage and restore-buffer/scan improvements, optional WAL
  policy and the explicitly selected experimental 8-GiB reserve profile.
- Bounded producer head/mempool handoff retry, stale-candidate rejection and
  visible candidate/PoB/retry counters; no empty-mempool substitution.
- Owned RPC sessions, deadlines, short writes, fragmented reads and cancellation.
- Native peer retention, explicit dial/advice/error/metadata policies, cache
  lifetime/eviction fixes and VM module/context allocation corrections.
- Preflight, diagnostics, recovery-first operator guidance and native artifact
  provenance independent from Koinos One's desktop version.

The single-copy capacity helper can retire only the current synthetic run's
verified completed destination pairs after recording evidence. This bounds
test workspace without changing native restore or deleting existing databases.

## Build and upgrade guidance

Dependency repairs are source/archive/hash pinned and built in owned output
directories: Protobuf, generated Koinos proto, JSON cleanup plus matching
exception/crypto SDK objects, gRPC call binding and cpp-libp2p listener lifetime.
Use a clean build when upgrading native C++ consumers; allocator-bearing return
types and control owners require matching headers and libraries. Existing
installed dependencies are not silently patched.
The gRPC archive default uses the existing `cpp-pm/grpc` tag; the old missing
`hunter-packages` URL is migrated in cached builds. Archive SHA-256 remains
`48f52c566a03b3bea26e8440798d2ff4ce181221935e5983fb9495e13618dd55`;
local/custom archive overrides retain their explicit hash verification.

Verify downloaded checksums and the exact source/version/binary identity in
the release build metadata. Keep a known observer launch and previous binary
for rollback. Stop the old process before opening the same database with a
replacement. Begin as an observer and follow the
[producer activation gate](../running-producer-node.md) before enabling a
producer. Publishing the release does not authorize keys, funds or production.

## Validation scope and remaining work

The [R15 M1 report](../validation/low-resource-lr2-m1-r15.md) identifies the
predecessor source, dependencies and binary. It passes 104 normal checks, both
CLI checks, 63 focused ASan/UBSan, 61 default-TSan cases, five equivalent pairs
per measured workload, a 100-block/12,800-test-transaction controlled chain
and full-history observer mixed reads, restart and interruption/recovery.
Its observer peak RSS is 419,278,848 bytes and adjusted host `MemAvailable`
stays at or above 2,921,375,744 bytes. The strict disk budget includes the
complete raw device and full recovery reserve. These measurements apply to
that exact predecessor, inputs and workload.

The combined release has its own source/binary and release checks. Downloaded
qualification records must identify those exact artifacts; older R15 or
alpha.2 results are supporting evidence, not a substitute for release testing.
Sanitizer closures and prebuilt-dependency exclusions remain explicit. No
whole-process race-freedom or universal heap ceiling is claimed.

M1 is complete for its identified implementation. Issue 9 remains open for
independent D1/P2/R1/V1/S1/Q1/H1 evidence. Stable versioning does not declare
those broader resource, lifecycle, historical and loaded-producer gates closed.
Koinos One GUI/submodule integration, operational deployment and mainnet
production activation are separately scoped.

See the [publication record](../validation/native-1.3.0-publication.md) for the
stable tag, actual native checksums, final observer/reopen measurements and
separate container publication evidence.
